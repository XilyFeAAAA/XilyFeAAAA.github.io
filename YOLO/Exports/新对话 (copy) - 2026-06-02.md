## 1. 八股

> 面试回答建议：先给一句 **核心结论**，再讲 **机制 / 公式 / 优缺点 / 工程细节**，最后补充 **常见坑与改进方向**。

---

### 1.1 Transformer

#### 架构

Transformer 的核心是用 **Self-Attention + FFN** 替代 RNN/CNN，实现对序列中任意位置的全局建模。

经典 Transformer 分为：

- **Encoder-only**：如 BERT，适合理解类任务。
- **Decoder-only**：如 GPT / LLaMA / Qwen，适合自回归生成。
- **Encoder-Decoder**：如原始 Transformer / T5，适合 Seq2Seq 任务。

LLM 中最常见的是 **Decoder-only Transformer**，单层结构通常为：

```text
Input Tokens
   ↓
Token Embedding + Position Encoding
   ↓
[ Transformer Block ] × N
   ↓
Final Norm
   ↓
LM Head
   ↓
Next Token Distribution
```

一个 Decoder Transformer Block 通常包含：

```text
x
│
├── RMSNorm / LayerNorm
│
├── Masked Multi-Head Self-Attention
│
├── Residual Add
│
├── RMSNorm / LayerNorm
│
├── FFN / MLP / SwiGLU
│
└── Residual Add
```

常见结构差异：

| 结构 | 特点 |
|---|---|
| Post-Norm | `x + Sublayer(LN(x))` 之前的早期 Transformer 常用，深层训练不稳定 |
| Pre-Norm | `x + Sublayer(Norm(x))`，LLM 常用，训练更稳定 |
| RMSNorm | 只归一化均方根，不减均值，计算更省，LLaMA 系常用 |
| SwiGLU FFN | 比 ReLU/GELU FFN 表达能力更强，现代 LLM 常用 |
| RoPE | 旋转位置编码，支持相对位置信息和一定长度外推 |
| GQA/MQA | 减少 KV Cache 和推理显存 |

---

#### Q/K/V 解决了什么问题

Self-Attention 的核心公式：

$$
\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

其中：

- **Q / Query**：当前位置想要查找什么信息。
- **K / Key**：每个位置提供什么索引特征。
- **V / Value**：真正被聚合的信息内容。

假设输入为：

$$
X \in \mathbb{R}^{B \times L \times d_{\text{model}}}
$$

通过三个线性变换得到：

$$
Q=XW_Q,\quad K=XW_K,\quad V=XW_V
$$

Q/K/V 的作用：

1. **解耦匹配与内容**
   - `QK^T` 负责计算 token 之间的相关性。
   - `V` 负责提供最终被加权汇聚的信息。
   - 如果不用 Q/K/V，而直接对原始 embedding 做相似度，会限制模型表达能力。

2. **允许不同子空间学习不同关系**
   - 多头注意力中，每个 head 有自己的 Q/K/V。
   - 不同 head 可以关注语法、实体、指代、位置、格式等不同模式。

3. **支持动态上下文建模**
   - Attention 权重由当前输入动态决定。
   - 相比固定卷积核，Self-Attention 能根据上下文自适应选择信息来源。

4. **支持并行计算**
   - RNN 依赖时间步递推。
   - Transformer 可以一次性计算整个序列的 Q/K/V，训练并行度高。

面试简答：

> Q/K/V 的设计本质上是把“我想找什么”“我有什么可被匹配的特征”“真正传递什么内容”三件事解耦，使注意力既能灵活匹配 token 关系，又能在不同子空间中聚合上下文信息。

---

#### 多层 transformer 叠加出现的问题

多层 Transformer 叠加可以提升模型表达能力，但也会带来训练与表示层面的问题。

常见问题：

1. **梯度消失 / 梯度爆炸**
   - 层数越深，反向传播路径越长。
   - 如果没有残差和归一化，深层 Transformer 很难稳定训练。

2. **表示坍塌 / 过平滑**
   - 多层 Self-Attention 不断混合 token 表示。
   - 深层后不同 token 的表示可能变得越来越相似，区分度下降。

3. **训练不稳定**
   - Attention logits 过大导致 softmax 极端化。
   - FFN 激活值过大可能引发 overflow / NaN。
   - Post-Norm 深层模型更容易不稳定。

4. **信息遗忘**
   - 原始输入信息在多层非线性变换后可能逐渐丢失。
   - 残差连接可以缓解该问题。

5. **计算和显存开销大**
   - Attention 复杂度为 $O(L^2d)$。
   - 层数增加后，激活显存、KV Cache、通信开销都会增加。

6. **Attention Head 冗余**
   - 很多 head 可能学到类似模式。
   - 大模型中存在 head redundancy，可以通过剪枝或 GQA/MQA 优化。

常见缓解方式：

| 问题 | 缓解方式 |
|---|---|
| 梯度不稳定 | Residual、Pre-Norm、梯度裁剪、合理初始化 |
| 表示坍塌 | 残差路径、LayerNorm/RMSNorm、增大宽度、调 attention 温度 |
| 显存过大 | FlashAttention、Gradient Checkpointing、ZeRO、TP |
| 长序列困难 | RoPE Scaling、Sparse Attention、滑窗 Attention |
| 深层训练难 | Pre-Norm、DeepNorm、ResScale、μParam 初始化 |

---

#### 残差连接作用？会带来什么问题？

残差连接形式：

$$
y = x + F(x)
$$

在 Transformer Block 中通常为：

```text
x = x + Attention(Norm(x))
x = x + FFN(Norm(x))
```

作用：

1. **缓解梯度消失**
   - 梯度可以通过恒等路径直接回传。
   - 深层网络更容易训练。

2. **保留原始信息**
   - 子层只需要学习增量修正，而不是重新学习完整表示。
   - 对语言模型尤其重要，因为 token 原始语义需要跨层保留。

3. **加快收敛**
   - 学习目标从 $H(x)$ 变为残差 $F(x)=H(x)-x$。
   - 优化难度降低。

4. **支持深层堆叠**
   - 没有残差时，几十层甚至上百层 Transformer 很难稳定训练。

可能带来的问题：

1. **Residual Stream 数值不断累积**
   - 多层相加可能导致激活尺度增大。
   - 需要 Norm、初始化缩放、Residual Scaling 控制。

2. **模型可能过度依赖捷径**
   - 子层学习不足，信息主要走 residual path。
   - 可能导致某些层贡献较小。

3. **表示各向异性 / 表示坍塌**
   - 残差流长期累加高频方向，可能导致 embedding 空间集中到少数方向。
   - 影响表示质量。

4. **Pre-Norm 下深层梯度虽稳定，但输出层表达可能偏弱**
   - Pre-Norm 的梯度路径稳定。
   - 但每层输出没有立即归一化，最后通常需要 Final Norm。

---

#### 各种 norm 的差异&作用

归一化的目标：

- 稳定激活分布。
- 缓解梯度爆炸 / 消失。
- 加快收敛。
- 降低初始化和学习率敏感性。

##### LayerNorm

对单个样本的 hidden dimension 做归一化：

$$
\mu=\frac{1}{d}\sum_i x_i
$$

$$
\sigma^2=\frac{1}{d}\sum_i(x_i-\mu)^2
$$

$$
\text{LN}(x)=\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}\gamma+\beta
$$

特点：

- NLP / Transformer 常用。
- 不依赖 batch size。
- 同时做 **去均值** 和 **缩放方差**。

##### RMSNorm

RMSNorm 不减均值，只根据均方根缩放：

$$
\text{RMSNorm}(x)=\frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2+\epsilon}}\gamma
$$

特点：

- 比 LayerNorm 计算更简单。
- 现代 LLM 常用，如 LLaMA。
- 实践中效果接近或优于 LayerNorm。
- 不引入 bias，数值更轻量。

##### BatchNorm

对 batch 维度统计均值方差：

- CV 中常用。
- NLP 中不常用于 Transformer。
- 原因：
  - 序列长度变化大。
  - batch size 小或分布变化时不稳定。
  - 自回归生成时 train/infer 行为不一致。

##### Pre-Norm vs Post-Norm

Post-Norm：

```text
x = Norm(x + Sublayer(x))
```

优点：

- 每层输出规范化，表示尺度规整。
- 原始 Transformer 使用。

缺点：

- 深层时梯度容易不稳定。

Pre-Norm：

```text
x = x + Sublayer(Norm(x))
```

优点：

- 梯度可以沿 residual path 稳定传播。
- 更适合深层 LLM。

缺点：

- 输出尺度可能随层数累积，需要 Final Norm。

对比总结：

| Norm | 归一化维度 | 是否去均值 | 是否依赖 Batch | LLM 常用程度 |
|---|---|---:|---:|---:|
| BatchNorm | Batch | 是 | 是 | 低 |
| LayerNorm | Hidden | 是 | 否 | 高 |
| RMSNorm | Hidden | 否 | 否 | 很高 |
| Pre-Norm | 结构设计 | - | 否 | 很高 |
| Post-Norm | 结构设计 | - | 否 | 较低 |

---

#### RoPE

RoPE，Rotary Position Embedding，旋转位置编码，是现代 LLM 中非常常见的位置编码方式。

核心思想：

> 不直接把位置向量加到 token embedding 上，而是在计算 attention 前，对 Q/K 按位置进行二维旋转，使点积天然包含相对位置信息。

对二维向量 $(x_1,x_2)$，位置 $m$ 对应旋转角 $\theta_m$：

$$
\begin{bmatrix}
x_1' \\
x_2'
\end{bmatrix}
=
\begin{bmatrix}
\cos \theta_m & -\sin \theta_m \\
\sin \theta_m & \cos \theta_m
\end{bmatrix}
\begin{bmatrix}
x_1 \\
x_2
\end{bmatrix}
$$

在高维中，每两个维度一组进行旋转。

RoPE 的性质：

1. **相对位置建模**
   - 经过旋转后，$q_m^T k_n$ 与相对距离 $m-n$ 有关。
   - 因此适合自回归语言模型。

2. **不增加额外参数**
   - RoPE 是确定性函数。
   - 相比 learned position embedding 参数更少。

3. **兼容 KV Cache**
   - 生成时每个 token 的 K/V 可以缓存。
   - RoPE 只需对当前位置 Q/K 做旋转。

4. **具有一定长度外推能力**
   - 但原始 RoPE 在超出训练长度很多时仍会退化。
   - 常见扩展方法：NTK Scaling、YaRN、LongRoPE、Position Interpolation。

RoPE 与绝对位置编码对比：

| 方法 | 方式 | 优点 | 缺点 |
|---|---|---|---|
| Sinusoidal PE | 加到 embedding | 无参数，可外推 | 表达有限 |
| Learned PE | 学习位置表 | 简单有效 | 难外推 |
| Relative PE | attention 中加入相对偏置 | 相对位置强 | 实现复杂 |
| RoPE | 旋转 Q/K | 相对位置、无参数、适合 LLM | 长距离外推需 scaling |

---

#### 有哪些减少 attention 计算量的方法

标准 Attention 复杂度：

- 计算复杂度：$O(L^2d)$
- 显存复杂度：$O(L^2)$
- KV Cache 推理显存：$O(B \cdot L \cdot n_{kv} \cdot d_{head})$

优化方法可以分为以下几类。

##### 1. 工程优化：不改变数学结果

| 方法 | 思路 | 优点 |
|---|---|---|
| FlashAttention | 分块计算 attention，避免显式存储完整 attention matrix | 精确 attention，省显存，速度快 |
| xFormers / SDPA | 使用高效 kernel | 易用 |
| KV Cache | 自回归推理缓存历史 K/V | 将每步重复计算降到最低 |

FlashAttention 仍是精确 attention，只是通过 tiling 和 online softmax 减少 HBM 读写。

##### 2. 减少 KV Head

| 方法 | 说明 |
|---|---|
| MHA | 每个 Q head 都有独立 K/V |
| MQA | 多个 Q head 共享一组 K/V |
| GQA | 多个 Q head 分组共享 K/V，是 MHA 和 MQA 的折中 |

优点：

- 显著减少 KV Cache。
- 提升推理吞吐。
- 对长上下文生成尤其重要。

##### 3. 稀疏 Attention

只计算部分 token 间注意力：

- Sliding Window Attention：只看局部窗口。
- Dilated Attention：间隔采样。
- Block Sparse Attention：块稀疏。
- Global + Local Attention：少数全局 token + 局部窗口。

优点：

- 复杂度可接近 $O(Lw)$。
- 适合长文本。

缺点：

- 可能损失全局依赖。
- kernel 实现复杂。

##### 4. 低秩 / 线性 Attention

将 softmax attention 近似成可线性计算的形式：

$$
\text{softmax}(QK^T)V \approx \phi(Q)(\phi(K)^TV)
$$

代表方法：

- Linear Attention
- Performer
- Linformer
- Nyströmformer

优点：

- 长序列复杂度低。

缺点：

- 通常效果不如标准 attention。
- 大规模 LLM 中主流程度不如 FlashAttention + GQA。

##### 5. 序列压缩

思路：

- 压缩历史 token。
- 只保留重要 token。
- 使用 memory token / summary token。
- Retrieval-Augmented Context。

代表：

- Token Pruning
- StreamingLLM
- Compressive Transformer
- Long-context memory methods

### 1.2 LoRA 微调

#### 原理

LoRA，Low-Rank Adaptation，是一种参数高效微调方法。

核心思想：

> 冻结原模型参数，只训练一个低秩增量矩阵，用少量参数近似全量微调中的权重更新。

对于原始线性层：

$$
y = Wx
$$

全量微调会直接更新 $W$：

$$
W' = W + \Delta W
$$

LoRA 假设 $\Delta W$ 是低秩的：

$$
\Delta W = BA
$$

其中：

- $A \in \mathbb{R}^{r \times d_{\text{in}}}$
- $B \in \mathbb{R}^{d_{\text{out}} \times r}$
- $r \ll \min(d_{\text{in}}, d_{\text{out}})$

前向变为：

$$
y = Wx + \frac{\alpha}{r}BAx
$$

训练时：

- 冻结 $W$。
- 只训练 $A$ 和 $B$。
- 通常 $A$ 随机初始化，$B$ 初始化为 0，保证训练初始时模型输出不变。

优点：

1. **参数量小**
   - 原线性层参数：$d_{\text{out}}d_{\text{in}}$
   - LoRA 参数：$r(d_{\text{in}}+d_{\text{out}})$

2. **显存占用低**
   - 不需要保存全量参数的 optimizer states。
   - 适合单卡或少卡微调。

3. **可插拔**
   - LoRA adapter 可以单独保存。
   - 推理时可以 merge 到原权重中。

4. **适合多任务**
   - 同一个 base model 可以挂多个 LoRA adapter。

缺点：

- 表达能力受 rank 限制。
- 对复杂任务可能不如 full fine-tuning。
- 加载多个 adapter 时管理复杂。
- 如果数据量很大、领域差异很大，可能需要更高 rank 或全参微调。

---

#### 参数选择

LoRA 常见超参数：

| 参数 | 含义 | 常见取值 |
|---|---|---|
| `r` | 低秩维度 | 4 / 8 / 16 / 32 / 64 |
| `alpha` | 缩放系数 | 16 / 32 / 64 / 128 |
| `dropout` | LoRA 分支 dropout | 0 ~ 0.1 |
| `target_modules` | 插入模块 | q_proj, v_proj, k_proj, o_proj, up/down/gate |
| `learning_rate` | 学习率 | 1e-5 ~ 2e-4 |
| `batch_size` | batch 大小 | 视显存而定 |
| `epochs` | 训练轮数 | 1 ~ 5 |

经验选择：

1. **rank r**
   - 小数据 / 简单风格迁移：`r=4~8`
   - 一般 SFT：`r=8~16`
   - 复杂领域任务：`r=32~64`
   - rank 越大，表达能力越强，但越容易过拟合，显存也更高。

2. **alpha**
   - 通常与 rank 同量级或更大。
   - 有效缩放为 $\alpha / r$。
   - 常见搭配：`r=8, alpha=16` 或 `r=16, alpha=32`。

3. **dropout**
   - 数据少时可以设 `0.05~0.1` 防止过拟合。
   - 数据多或追求拟合能力时可设 `0`。

4. **学习率**
   - LoRA 学习率通常高于全参微调。
   - 常见：`1e-4`、`2e-4`。
   - 如果 loss 震荡或模型退化，降低学习率。

5. **训练轮数**
   - 指令微调通常不宜过多 epoch。
   - 过多会导致格式过拟合、知识遗忘、泛化下降。

调参优先级建议：

```text
数据质量 > 学习率 > target_modules > rank r > alpha > dropout
```

---

#### LoRA 加在哪些模块上

Transformer 中 LoRA 常加在线性层上。

##### Attention 模块

常见模块：

- `q_proj`
- `k_proj`
- `v_proj`
- `o_proj`

不同选择：

| 位置 | 作用 | 适用场景 |
|---|---|---|
| q_proj | 改变 query 表示，影响注意力查询方式 | 常用 |
| k_proj | 改变 key 表示，影响匹配空间 | 中等 |
| v_proj | 改变 value 内容，影响聚合信息 | 非常常用 |
| o_proj | 改变 attention 输出投影 | 常用 |

常见配置：

```text
target_modules = ["q_proj", "v_proj"]
```

或：

```text
target_modules = ["q_proj", "k_proj", "v_proj", "o_proj"]
```

##### FFN / MLP 模块

LLaMA 类模型常见：

- `gate_proj`
- `up_proj`
- `down_proj`

FFN 参数量通常占 Transformer 大头，加 LoRA 后对任务适配能力更强。

适合：

- 领域知识注入。
- 复杂推理格式学习。
- 风格迁移。
- 工具调用格式学习。

##### Embedding / LM Head

一般不优先加，除非：

- 新增大量特殊 token。
- 任务强依赖词表扩展。
- 领域术语特别多。

##### 总结建议

| 目标 | 推荐 target_modules |
|---|---|
| 轻量指令微调 | q_proj, v_proj |
| 通用 SFT | q,k,v,o |
| 复杂任务适配 | q,k,v,o + gate,up,down |
| 领域知识增强 | attention + FFN |
| 新 token 学习 | embedding / lm_head 也训练 |

---

#### 多轮对话微调

多轮对话 SFT 的目标是让模型学习：

- 角色遵循。
- 上下文记忆。
- 多轮指代消解。
- 对话状态跟踪。
- 输出格式一致性。
- 拒答与安全边界。

常见数据格式：

```json
{
  "messages": [
    {"role": "system", "content": "你是一个有帮助的助手。"},
    {"role": "user", "content": "请解释 Transformer。"},
    {"role": "assistant", "content": "Transformer 是一种..."},
    {"role": "user", "content": "那 RoPE 呢？"},
    {"role": "assistant", "content": "RoPE 是..."}
  ]
}
```

训练时通常：

1. 使用 chat template 拼接为模型输入。
2. 只对 assistant 部分计算 loss。
3. user/system token 设置 label 为 `-100`。
4. 保留特殊 token，如 `<|user|>`、`<|assistant|>`、`<eos|>`。
5. 每个 assistant 回复末尾最好加 EOS，避免模型生成不停。

##### 为什么只训 assistant 部分？

因为模型推理时需要生成 assistant 回复，而不是复现用户问题。

若对 user 也计算 loss：

- 模型会学习生成用户输入。
- 训练目标与推理目标不一致。
- 可能降低对话质量。

##### 多轮样本构造注意点

| 问题 | 建议 |
|---|---|
| 上下文过长 | 截断早期轮次或构造 sliding window |
| assistant 回复太长 | 控制长度分布，避免长样本主导 loss |
| 格式不统一 | 统一 chat template |
| 角色混乱 | 明确 system/user/assistant 边界 |
| 多轮质量差 | 过滤前后矛盾、答非所问、幻觉严重样本 |
| EOS 缺失 | 每轮 assistant 末尾加 EOS |

### 1.3 Supervised Finetune

#### 原理

SFT，Supervised Fine-Tuning，监督微调，是用高质量指令-回答数据对预训练模型进行有监督训练。

训练目标仍然是语言模型的 next-token prediction：

$$
\mathcal{L}_{\text{SFT}}
= - \sum_{t} \log p_\theta(y_t \mid x, y_{<t})
$$

其中：

- $x$ 是 prompt / instruction / conversation history。
- $y$ 是 assistant response。
- 通常只在 response token 上计算 loss。

SFT 的作用：

1. **把 base model 对齐成 chat model**
   - base model 只会续写文本。
   - SFT 后模型学会遵循指令、回答问题、保持格式。

2. **注入任务格式**
   - 如代码生成、工具调用、JSON 输出、数学解题格式。

3. **提升可用性**
   - 让模型输出更清晰、完整、安全。

4. **为 RLHF / DPO 提供初始策略**
   - RL 阶段需要一个已经能稳定回答的 policy。
   - SFT 是 RLHF 的基础。

SFT 和预训练的区别：

| 维度 | Pretrain | SFT |
|---|---|---|
| 数据 | 海量通用文本 | 高质量指令数据 |
| 目标 | 续写任意文本 | 生成期望回答 |
| Loss | 所有 token | 多数只训 assistant token |
| 作用 | 学知识和语言能力 | 学指令遵循和回答格式 |
| 数据规模 | TB 级 | 千到百万级样本 |

---

#### sft 到什么程度可以 rl

SFT 到可以进入 RL 阶段，一般需要满足：

> 模型已经具备基本指令遵循能力，能稳定产出合法、可评估、非崩坏的回答。

判断标准：

1. **格式稳定**
   - 能正确遵循 chat template。
   - 不乱输出 user/system。
   - 需要 JSON / code / tool call 时格式基本合法。

2. **任务成功率达到 baseline**
   - 在目标任务上已经有可接受准确率。
   - RL 不是从 0 教模型，而是在可用策略上进一步优化偏好或奖励。

3. **回复质量稳定**
   - 不频繁空回复。
   - 不无限重复。
   - 不大面积幻觉或跑题。

4. **reward model / rule reward 可区分**
   - 如果模型输出太差，reward 信号没有意义。
   - RL 会非常不稳定。

5. **KL 不会一开始就过大**
   - 初始 policy 应该接近 reference model。
   - 否则 RL 容易把模型推离语言流形。

6. **离线评测无明显退化**
   - 通用能力、推理能力、安全性没有明显下降。
   - SFT 不能过拟合到少数模板。

经验上：

- 如果 RL 是做数学 / 代码 / 工具调用，SFT 至少要让模型学会完整解题格式。
- 如果 RL 是做 preference alignment，SFT 至少要让模型回答可读、有帮助。
- 如果 RL 是 rule-based reward，SFT 输出必须能被规则解析。

一句话：

> SFT 不需要做到最优，但要做到“可用且可优化”；RL 擅长在已有能力上做偏好与策略改进，不擅长从完全不会开始学习。

---

#### 怎么评估 sft 效果

评估可以分为自动指标、模型裁判、人评和线上指标。

##### 1. Loss / PPL

- 验证集 loss 下降说明模型拟合数据。
- PPL：

$$
\text{PPL} = \exp(\text{CrossEntropy})
$$

注意：

- loss 低不一定回答好。
- 如果验证集与训练集分布太近，容易高估效果。
- 对只训 assistant 的 SFT，需要只在 assistant token 上算 loss。

##### 2. 指令遵循能力

看模型是否：

- 回答用户问题。
- 不遗漏约束。
- 遵循格式要求。
- 能处理多轮上下文。
- 不输出无关内容。

##### 3. 任务指标

根据任务类型选择：

| 任务 | 指标 |
|---|---|
| 分类 | Accuracy / F1 |
| 抽取 | EM / F1 |
| 翻译 | BLEU / COMET |
| 摘要 | ROUGE / 人评 |
| 代码 | pass@k |
| 数学 | exact match / rule judge |
| 工具调用 | JSON parse rate / tool accuracy |
| RAG | faithfulness / answer correctness |

##### 4. 生成质量

关注：

- helpfulness
- correctness
- completeness
- conciseness
- harmlessness
- hallucination rate
- repetition rate

##### 5. 对比评测

常用方式：

- SFT model vs base model。
- 新 checkpoint vs old checkpoint。
- A/B pairwise comparison。
- GPT-judge / reward model judge。
- 人工 blind review。

##### 6. 泛化与鲁棒性

测试：

- 未见过领域。
- 长 prompt。
- 多轮追问。
- 噪声输入。
- 对抗 prompt。
- 不同语言。

---

#### sft 数据怎么评估好坏

SFT 数据质量往往比数量更重要。

好的 SFT 数据应该具备：

1. **指令清晰**
   - 用户意图明确。
   - 约束条件完整。
   - 不含歧义或错误前提。

2. **回答高质量**
   - 正确。
   - 完整。
   - 结构清晰。
   - 不胡编。
   - 不过度冗长。

3. **格式一致**
   - 统一 chat template。
   - role 标注正确。
   - assistant 回复边界明确。
   - EOS 正确。

4. **分布合理**
   - 覆盖目标任务。
   - 难度有层次。
   - 长短样本均衡。
   - 不被单一模板支配。

5. **无污染**
   - 去重。
   - 去除 benchmark 泄漏。
   - 去除乱码、截断、HTML 垃圾、重复广告。

6. **安全与合规**
   - 过滤敏感隐私。
   - 过滤违法危险内容。
   - 对拒答类样本进行规范化。

##### 数据质量检查指标

| 指标 | 说明 |
|---|---|
| 长度分布 | prompt/response token 长度是否异常 |
| 去重率 | 重复样本比例 |
| 空回复率 | assistant 是否为空 |
| 格式错误率 | role/chat template 是否错误 |
| 语言比例 | 中英文或多语言分布 |
| 毒性比例 | 是否含有害内容 |
| benchmark overlap | 是否污染评测集 |
| perplexity filter | 过高 PPL 样本可能是噪声 |
| reward score | 用 RM 或 LLM judge 打分 |

##### 常见坏数据

- 问答不匹配。
- assistant 回答事实错误。
- 多轮上下文前后矛盾。
- 训练集中混入大量免责声明模板。
- 样本被截断但没有标记。
- JSON / 代码格式不合法。
- 过多“作为一个 AI 模型……”模板化回答。
- 高重复 synthetic data。

---

#### 样本长度差异大怎么办

样本长度差异大会导致：

- padding 浪费显存。
- 长样本主导 loss。
- batch 内 token 数不稳定。
- 训练速度下降。
- OOM 风险增加。

解决方法：

##### 1. 按长度分桶 batching

将长度相近的样本放入同一个 batch：

```text
short samples → batch A
medium samples → batch B
long samples → batch C
```

优点：

- 减少 padding。
- 提升吞吐。
- 降低显存波动。

##### 2. Dynamic Padding

每个 batch padding 到当前 batch 最大长度，而不是全局最大长度。

##### 3. Packing

把多个短样本拼接到同一个 sequence 中：

```text
sample1 <eos> sample2 <eos> sample3 <eos>
```

优点：

- 显著提升 token 利用率。

注意：

- 必须正确构造 attention mask。
- 不同样本之间不能互相 attention，或者用 EOS 明确隔开。
- labels 需要正确 mask。

##### 4. 截断策略

对于超长样本：

- 保留开头 + 结尾。
- 多轮对话保留最近轮次。
- 对 RAG 保留 query 和高相关文档。
- 对推理数据尽量不要截断 chain-of-thought 中间部分。

##### 5. Token-based Batch

不用固定样本数，而是固定每个 batch 的 token 数：

```text
max_tokens_per_batch = 32768
```

这样 batch 更稳定。

##### 6. Loss 归一化

如果直接按 token 平均，长样本贡献更多 token。

可选：

- token-level average：每个 token 权重相同。
- sample-level average：每个样本权重相同。
- task-balanced sampling：不同任务采样均衡。

### 1.4 RLHF

#### rl 比 sft 好在哪

SFT 是模仿学习，RLHF 是基于奖励优化策略。

SFT 的问题：

1. **只能学习示范答案**
   - 数据里没有的更优答案学不到。
   - 模型倾向于模仿平均行为。

2. **无法直接优化人类偏好**
   - 交叉熵只要求最大化参考答案概率。
   - 但开放式问题有多个可接受答案。

3. **暴露偏差**
   - 训练时看到 gold prefix。
   - 推理时基于自己的历史输出生成。
   - 错误会累积。

4. **难以处理不可微指标**
   - 如代码 pass、数学答案正确性、人工偏好、工具调用成功率。

RL 的优势：

1. **可直接优化目标奖励**
   - reward 可以来自人类偏好、规则、单元测试、RM、LLM judge。

2. **支持探索**
   - 模型可以生成多个候选，通过奖励筛选更优行为。

3. **更适合开放式对齐**
   - helpful / harmless / honest 等偏好难用单一标准答案表达。

4. **可优化长程结果**
   - 对多步推理、agent 工具调用、游戏环境等更有效。

但 RL 也有风险：

- 训练不稳定。
- reward hacking。
- KL 失控。
- 熵崩塌。
- 模型语言质量退化。
- 对 reward 设计非常敏感。

一句话：

> SFT 让模型“会做”，RL 让模型“更偏向做得好”；SFT 学示范分布，RL 优化奖励目标。

---

#### 重要性采样

重要性采样用于解决：

> 我们想估计目标分布 $p(x)$ 下的期望，但样本来自另一个分布 $q(x)$。

目标：

$$
\mathbb{E}_{x \sim p}[f(x)] = \int f(x)p(x)dx
$$

如果只能从 $q(x)$ 采样：

$$
\mathbb{E}_{x \sim p}[f(x)]
= \int f(x)\frac{p(x)}{q(x)}q(x)dx
= \mathbb{E}_{x \sim q}\left[f(x)\frac{p(x)}{q(x)}\right]
$$

其中：

$$
w(x)=\frac{p(x)}{q(x)}
$$

称为 importance weight。

在 RL 中，常见于 off-policy 估计。比如数据由旧策略 $\pi_{\text{old}}$ 采样，但想优化新策略 $\pi_\theta$：

$$
\rho_t = \frac{\pi_\theta(a_t|s_t)}{\pi_{\text{old}}(a_t|s_t)}
$$

PPO 中的 ratio 就是重要性采样比值：

$$
r_t(\theta)=\frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\text{old}}}(a_t|s_t)}
$$

问题：

1. **方差大**
   - 如果 $p/q$ 很大，少数样本权重极高。
   - 估计不稳定。

2. **support mismatch**
   - 如果 $q(x)=0$ 但 $p(x)>0$，无法估计。

3. **需要裁剪**
   - PPO 使用 clipping 限制 ratio：
   - $r_t \in [1-\epsilon,1+\epsilon]$

面试简答：

> 重要性采样通过乘上目标分布和采样分布的概率比，把来自旧分布的样本重加权为目标分布下的估计；在 PPO 中体现为新旧策略概率比，但该比值方差可能很大，所以需要 clip 或 KL 约束。

---

#### KL divergence

KL 散度衡量两个概率分布的差异。

定义：

$$
D_{KL}(P||Q)=\sum_x P(x)\log\frac{P(x)}{Q(x)}
$$

连续形式：

$$
D_{KL}(P||Q)=\int P(x)\log\frac{P(x)}{Q(x)}dx
$$

性质：

- 非负：$D_{KL}(P||Q)\ge 0$
- 不对称：$D_{KL}(P||Q)\neq D_{KL}(Q||P)$
- 当且仅当 $P=Q$ 时为 0。

##### Forward KL vs Reverse KL

Forward KL：

$$
D_{KL}(P_{\text{data}}||P_\theta)
$$

特点：

- 如果数据分布有多个模式，模型倾向覆盖所有模式。
- mode-covering。
- 常见于最大似然训练。

Reverse KL：

$$
D_{KL}(P_\theta||P_{\text{data}})
$$

特点：

- 模型倾向选择高概率模式，避免低概率区域。
- mode-seeking。
- 容易模式坍塌。

##### RLHF 中的 KL

RLHF 中常加入 KL penalty，约束 policy 不要偏离 reference model 太远：

$$
R'(x,y)=R(x,y)-\beta D_{KL}(\pi_\theta(y|x)||\pi_{\text{ref}}(y|x))
$$

作用：

1. 保持语言质量。
2. 防止 reward hacking。
3. 避免策略更新过大。
4. 保留 SFT 模型已有能力。
5. 稳定训练。

如果 KL 太大：

- 模型偏离参考策略。
- 可能语言退化、胡言乱语。
- reward 可能升高但真实质量下降。

如果 KL 太小：

- 模型几乎不学习。
- reward 提升有限。

---

#### Policy Gradient

强化学习目标：

$$
J(\theta)=\mathbb{E}_{\tau \sim \pi_\theta}[R(\tau)]
$$

希望最大化策略 $\pi_\theta$ 的期望奖励。

Policy Gradient 定理：

$$
\nabla_\theta J(\theta)
=
\mathbb{E}_{\tau \sim \pi_\theta}
\left[
\nabla_\theta \log \pi_\theta(\tau) R(\tau)
\right]
$$

对于 token-level LLM：

$$
\nabla_\theta J(\theta)
=
\mathbb{E}
\left[
\sum_t \nabla_\theta \log \pi_\theta(y_t|x,y_{<t}) A_t
\right]
$$

其中 $A_t$ 是 advantage。

直观理解：

- 如果某个动作带来高奖励，就提高它的概率。
- 如果某个动作带来低奖励，就降低它的概率。

常用 loss 写法：

$$
\mathcal{L}_{PG}(\theta)
=
-\mathbb{E}_t[\log\pi_\theta(a_t|s_t)A_t]
$$

因为优化器默认最小化 loss，所以前面加负号。

##### 为什么用 advantage 而不是 return？

Return 方差大，因此引入 baseline：

$$
A_t = Q(s_t,a_t)-V(s_t)
$$

如果 $A_t>0$，说明动作比平均水平好，提高概率。

如果 $A_t<0$，说明动作比平均水平差，降低概率。

---

#### 蒙特卡洛估计

蒙特卡洛估计用采样平均近似期望。

如果：

$$
\mu=\mathbb{E}[f(x)]
$$

采样 $x_1,\dots,x_N$，则：

$$
\hat{\mu}=\frac{1}{N}\sum_{i=1}^{N}f(x_i)
$$

在 RL 中，蒙特卡洛 return：

$$
G_t = \sum_{k=t}^{T}\gamma^{k-t}r_k
$$

特点：

| 优点 | 缺点 |
|---|---|
| 无偏 | 方差大 |
| 不需要价值函数 | 样本效率低 |
| 适合 episode 完整采样 | 不能很好在线更新 |

在 LLM RLHF 中：

- 通常一个完整 response 结束后才得到 reward。
- 可以把最终 reward 分配给所有 token。
- 这本质上接近蒙特卡洛估计。

问题：

- 长文本中每个 token 都共享最终 reward，credit assignment 很粗。
- reward 方差大。
- 需要 advantage normalization、baseline 或 value model 降方差。

---

#### 广义优势估计

GAE，Generalized Advantage Estimation，用于在 bias 和 variance 之间折中估计 advantage。

TD residual：

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

GAE：

$$
A_t^{GAE(\gamma,\lambda)}
=
\sum_{l=0}^{\infty}(\gamma\lambda)^l\delta_{t+l}
$$

其中：

- $\gamma$：折扣因子。
- $\lambda$：控制 bias-variance tradeoff。

特殊情况：

| λ | 含义 |
|---|---|
| $\lambda=0$ | 只用一步 TD，方差小，偏差大 |
| $\lambda=1$ | 接近 Monte Carlo，偏差小，方差大 |

作用：

1. 降低 policy gradient 方差。
2. 提升 PPO 训练稳定性。
3. 利用 value function 做 baseline。
4. 兼顾短期和长期奖励。

在 LLM RLHF 中：

- 如果只有 response-level reward，可以在末尾给 reward。
- Value model 估计每个 token 状态价值。
- GAE 将终局 reward 传播到每个 token。

---

#### TD Error

TD Error 衡量当前价值估计和 bootstrap target 的差距：

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

含义：

- 如果 $\delta_t > 0$：实际结果比预期好。
- 如果 $\delta_t < 0$：实际结果比预期差。

TD Error 用途：

1. **训练价值函数**
   - 最小化：
   $$
   \mathcal{L}_V = (\delta_t)^2
   $$

2. **构造 Advantage**
   - GAE 基于 TD residual 累加。

3. **降低方差**
   - 相比纯 MC return，TD 使用 bootstrap，方差更低。

TD vs MC：

| 方法 | 是否 bootstrap | 偏差 | 方差 |
|---|---:|---:|---:|
| MC | 否 | 低 | 高 |
| TD | 是 | 高一些 | 低 |
| GAE | 部分 | 可调 | 可调 |

---

#### PPO

PPO，Proximal Policy Optimization，是 RLHF 中经典算法之一。

PPO 使用新旧策略概率比：

$$
r_t(\theta)
=
\frac{\pi_\theta(a_t|s_t)}
{\pi_{\theta_{\text{old}}}(a_t|s_t)}
$$

Vanilla policy gradient objective：

$$
L^{PG}(\theta)=\mathbb{E}_t[r_t(\theta)A_t]
$$

PPO Clip objective：

$$
L^{CLIP}(\theta)
=
\mathbb{E}_t
\left[
\min
\left(
r_t(\theta)A_t,
\text{clip}(r_t(\theta),1-\epsilon,1+\epsilon)A_t
\right)
\right]
$$

作用：

- 限制策略每次更新幅度。
- 防止新策略偏离旧策略太多。
- 提高训练稳定性。

RLHF PPO 常见组成：

1. **Policy Model**
   - 当前训练的模型。

2. **Reference Model**
   - 通常是 SFT model 冻结副本。
   - 用于 KL penalty。

3. **Reward Model**
   - 输入 prompt + response，输出 reward。

4. **Value Model**
   - 估计每个 token 的 value。
   - 用于计算 advantage。

PPO loss 通常包括：

$$
\mathcal{L}
=
\mathcal{L}_{policy}
+
c_v\mathcal{L}_{value}
-
c_e\mathcal{H}
+
\beta\mathcal{L}_{KL}
$$

其中：

- policy loss：优化 reward。
- value loss：训练 critic。
- entropy bonus：鼓励探索。
- KL penalty：约束偏离 reference。

PPO 的缺点：

- 需要 reward model 和 value model。
- 训练复杂，显存占用大。
- 超参数敏感。
- 容易 reward hacking。
- 在 LLM 中实现成本较高。

---

#### DPO

DPO，Direct Preference Optimization，是一种不显式训练 reward model、不跑在线 RL 的偏好优化方法。

数据形式：

```text
prompt x
chosen response y_w
rejected response y_l
```

DPO 目标来源于 Bradley-Terry 偏好模型和 KL-constrained RL，可以写为：

$$
\mathcal{L}_{DPO}
=
-\mathbb{E}
\left[
\log \sigma
\left(
\beta
\left[
\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}
-
\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}
\right]
\right)
\right)
\right]
$$

直观理解：

- 提高 chosen 相对 reference 的概率。
- 降低 rejected 相对 reference 的概率。
- 用 reference 约束模型不要偏离太多。

优点：

1. 实现简单。
2. 不需要 reward model。
3. 不需要 PPO 的采样和 value model。
4. 训练稳定。
5. 适合偏好数据。

缺点：

1. 依赖高质量 preference pair。
2. 本质是离线优化，探索能力弱。
3. 对 chosen/rejected 差异敏感。
4. 不适合需要环境交互的 agentic RL。
5. 容易过拟合偏好数据风格。

DPO vs PPO：

| 维度 | PPO | DPO |
|---|---|---|
| 是否在线采样 | 是 | 否 |
| 是否需要 RM | 通常需要 | 不需要 |
| 是否需要 Value | 需要 | 不需要 |
| 训练复杂度 | 高 | 低 |
| 探索能力 | 较强 | 弱 |
| 适合任务 | RLHF、环境交互 | 偏好对齐 |

---

#### GRPO

GRPO，Group Relative Policy Optimization，常用于大模型推理能力增强场景。

核心思想：

> 对同一个 prompt 采样多个 responses，使用组内相对奖励构造 advantage，避免额外训练 value model。

对于同一个 prompt $x$，采样 $G$ 个回答：

$$
\{y_1,y_2,\dots,y_G\}
$$

获得奖励：

$$
\{r_1,r_2,\dots,r_G\}
$$

组内归一化 advantage：

$$
A_i = \frac{r_i - \text{mean}(r)}{\text{std}(r)+\epsilon}
$$

然后用 PPO-like objective 优化 policy。

优点：

1. **不需要 value model**
   - 降低显存和训练复杂度。

2. **适合 rule-based reward**
   - 数学答案、代码测试、格式检查等。

3. **组内比较稳定**
   - 同一个 prompt 下比较多个回答，减少 prompt 难度差异影响。

4. **鼓励探索多样解法**
   - 多采样可以发现高 reward trajectory。

缺点：

- 每个 prompt 需要采样多个回答，生成成本高。
- 如果组内 reward 全一样，advantage 信号弱。
- reward 设计不好仍会 reward hacking。
- 对采样温度、组大小、KL 系数敏感。

适用场景：

- 数学推理。
- 代码生成。
- 可验证任务。
- 多候选答案优化。
- DeepSeek-R1 类 reasoning RL。

---

#### DAPO

DAPO，Decoupled Clip and Dynamic sAmpling Policy Optimization，是对 GRPO/PPO 类方法的改进思路，常用于提升大模型 RL 训练的稳定性和效率。

核心关注点：

1. **解耦 clipping**
   - 对正负 advantage 使用不同裁剪策略。
   - 避免好样本被过度限制，坏样本更新不足。

2. **动态采样**
   - 根据训练阶段、prompt 难度、reward 分布调整采样。
   - 过滤无信息样本，例如组内 reward 全 0 或全 1。

3. **提升有效梯度比例**
   - 如果一个 prompt 的多个 response 奖励完全相同，则 advantage 接近 0。
   - 这类样本对训练贡献小，可以降低采样概率。

4. **稳定长链推理训练**
   - 对超长 response、重复输出、格式错误进行约束。
   - 配合 length penalty、KL penalty、防止熵崩塌。

直观理解：

> DAPO 希望解决 GRPO 中“采样贵但有效样本少”“clip 过于粗糙”“训练信号不均衡”的问题，通过动态筛选和更细粒度的 policy update 提高 RL 效率。

面试回答时可以说：

- GRPO 用组内相对奖励替代 value model。
- DAPO 在此基础上进一步优化样本利用率和 clipping 策略。
- 它更关注大模型 reasoning RL 中的有效梯度、长度控制和训练稳定性。

---

#### GSPO

GSPO，Group Sequence Policy Optimization，可以理解为一种更偏 **sequence-level** 的组相对策略优化思路。

和 token-level PPO/GRPO 不同，GSPO 更强调：

> 对完整 response 序列作为整体进行概率比、奖励和优化，而不是过度依赖 token-level credit。

常见动机：

1. **LLM 的奖励多是序列级**
   - 数学答案对不对、代码是否通过测试，通常只有完整输出后才知道。
   - token-level advantage 可能噪声很大。

2. **减少 token-level ratio 的不稳定**
   - 长序列中 token 概率比相乘或累积容易数值不稳定。
   - sequence-level 处理更贴近最终目标。

3. **适合组内相对比较**
   - 同一个 prompt 多个 response。
   - 根据整体 reward 进行相对优化。

可理解为：

$$
r(\theta)
=
\frac{\pi_\theta(y|x)}
{\pi_{\theta_{\text{old}}}(y|x)}
=
\exp
\left(
\log\pi_\theta(y|x)
-
\log\pi_{\theta_{\text{old}}}(y|x)
\right)
$$

其中：

$$
\log\pi_\theta(y|x)=\sum_t \log\pi_\theta(y_t|x,y_{<t})
$$

优点：

- 更符合 sequence-level reward。
- 对 reasoning / code / agent trajectory 更自然。
- 可以减少逐 token 信号噪声。

问题：

- 长序列 logprob 累加后尺度受长度影响。
- 需要长度归一化或合理 clipping。
- credit assignment 仍然困难。
- 对超长输出可能有偏置。

---

#### agentic rl 的 credit assignment

Agentic RL 中，模型不仅生成文本，还会：

- 调用工具。
- 查询网页。
- 写代码并执行。
- 多步规划。
- 与环境交互。
- 根据 observation 继续决策。

Credit assignment 指的是：

> 最终成功或失败后，如何判断哪些中间动作应该被奖励或惩罚。

为什么难？

1. **奖励延迟**
   - 最终结果很晚才出现。
   - 前面的动作很难知道贡献。

2. **轨迹长**
   - 一个任务可能包含几十步 action-observation。
   - 方差很大。

3. **动作类型复杂**
   - 文本推理、工具调用、参数选择、代码执行都可能影响结果。

4. **部分可观测**
   - agent 不一定知道环境完整状态。
   - 错误可能来自信息不足。

5. **非唯一解**
   - 多条轨迹都可能成功。
   - 很难定义标准中间步骤。

缓解方法：

| 方法 | 思路 |
|---|---|
| Step-level reward | 对中间步骤打分 |
| Process Reward Model | 评估推理过程每一步 |
| Outcome Reward Model | 只评估最终结果 |
| Tool feedback | 工具执行结果作为环境 reward |
| Self-consistency | 多轨迹投票 |
| MCTS / Tree Search | 搜索高价值轨迹 |
| Hindsight relabeling | 失败轨迹中提取部分成功步骤 |
| Credit decomposition | 把总奖励分解到 action/span/tool call |
| Advantage normalization | 降低不同任务难度差异 |

Agent 任务中常用奖励：

- 最终答案正确。
- 工具调用成功。
- API 参数合法。
- 检索结果相关。
- 代码通过测试。
- 步数更少。
- 不泄漏隐私。
- 不执行危险操作。

#### RLHF 训练的指标

RLHF 训练不能只看 reward，需要同时看多个指标。

##### 核心训练指标

| 指标 | 含义 | 异常表现 |
|---|---|---|
| reward | 奖励模型或规则奖励 | 过快上升可能 reward hacking |
| KL | policy 与 reference 差异 | 过大表示跑偏，过小表示没学 |
| policy loss | 策略优化损失 | 剧烈震荡表示不稳定 |
| value loss | critic 拟合误差 | 过大表示 advantage 不准 |
| entropy | 输出分布熵 | 快速下降可能熵崩塌 |
| clip fraction | PPO ratio 被裁剪比例 | 过高表示更新过大 |
| approx KL | 新旧 policy 差异 | PPO early stop 常用 |
| response length | 输出长度 | 可能被 reward 利用 |
| win rate | 相对 baseline 胜率 | 最重要的离线指标之一 |
| pass rate | 数学/代码任务通过率 | rule reward 任务核心指标 |

##### 如何判断 early stop

可以考虑 early stop 的情况：

1. **验证集 win rate 不再提升**
   - reward 继续升，但真实评测不升，可能过拟合 RM。

2. **KL 超过阈值**
   - 例如 target KL 的 1.5~2 倍。
   - 表示 policy 偏离 reference 太多。

3. **entropy 快速下降**
   - 输出多样性消失。
   - 模型开始模板化、重复。

4. **reward 上升但人工质量下降**
   - 典型 reward hacking。

5. **response length 异常增长或缩短**
   - 模型利用长度偏置骗 reward。

6. **通用 benchmark 退化**
   - 数学提升但常识/对话能力大幅下降，需要停止或调低 KL。

7. **clip fraction 长期过高**
   - 更新过猛，PPO 大量样本被 clip。

一个实用判断：

```text
如果 reward ↑，但 win rate / pass rate 不再 ↑，
同时 KL ↑、entropy ↓、长度异常，
通常应该 early stop 或减小学习率 / 增大 KL penalty。
```

#### 熵崩塌

熵衡量模型输出分布的不确定性：

$$
H(\pi)=-\sum_a \pi(a|s)\log\pi(a|s)
$$

熵崩塌指：

> 策略分布变得过于尖锐，模型只会输出少数模式，探索和多样性快速下降。

表现：

- 输出高度模板化。
- 反复使用固定句式。
- 重复 token / 重复段落。
- temperature 稍低就退化。
- pass@1 可能升，但 pass@k 多样性下降。
- 对开放问题回答变窄。

原因：

1. **奖励过于单一**
   - 模型只学会一种高 reward 模式。

2. **KL 约束太弱**
   - policy 远离 reference。

3. **学习率太大**
   - 更新过猛。

4. **PPO clip / ratio 控制不当**
   - 策略分布快速尖锐。

5. **只奖励最终正确，不奖励过程多样性**
   - reasoning 模型容易形成固定模板。

6. **训练太久**
   - 后期过拟合 reward。

缓解方法：

| 方法 | 作用 |
|---|---|
| Entropy bonus | 鼓励探索 |
| 增大 KL penalty | 约束 reference |
| 降低学习率 | 减小更新幅度 |
| Early stop | 防止过训练 |
| 多样化 prompts | 避免模板过拟合 |
| reward 去长度/模板偏置 | 防止利用捷径 |
| 多样性奖励 | 鼓励不同解法 |
| 保留 SFT 混合训练 | 减少语言能力退化 |

---

#### RL数据和SFT数据需要有重合吗？

不强制需要重合，但二者分布最好相关。

##### 可以不重合

RL 数据可以来自：

- 新 prompts。
- 用户线上问题。
- hard prompts。
- 数学/代码可验证题。
- 对抗样本。
- SFT 没覆盖的高价值场景。

原因：

- SFT 负责打基础。
- RL 负责优化奖励和偏好。
- RL 可以专门针对 SFT 弱点补强。

##### 但不能完全分布断裂

如果 RL prompts 与 SFT 差异太大：

- 初始 policy 输出质量差。
- reward 信号噪声大。
- KL 约束难调。
- 训练容易不稳定。
- 可能灾难性遗忘。

##### 最佳实践

| 数据关系 | 效果 |
|---|---|
| 完全相同 | 稳定，但提升有限，容易过拟合 |
| 部分重合 + 新 hard data | 最常见，效果较好 |
| 完全不相关 | 风险大，不推荐 |
| RL 覆盖 SFT 弱点 | 推荐 |

建议：

1. SFT 数据覆盖基本格式和能力。
2. RL 数据重点覆盖偏好、难题、可验证任务。
3. 保持 prompt 分布相近，但 response 不必相同。
4. 可混入少量 SFT loss 防止遗忘。
5. 评估集必须独立，避免训练污染。

一句话：

> RL 数据不需要和 SFT 数据完全重合，但最好来自相近任务分布；SFT 解决“会不会”，RL 解决“好不好”。

### 1.5 分布式训练

#### Data Parallel

Data Parallel，数据并行，是最基本的分布式训练方式。

核心思想：

> 每张 GPU 保存一份完整模型，处理不同 mini-batch，反向后同步梯度。

流程：

```text
GPU0: batch0 → forward/backward → grad0
GPU1: batch1 → forward/backward → grad1
GPU2: batch2 → forward/backward → grad2
GPU3: batch3 → forward/backward → grad3
                  ↓
              all-reduce
                  ↓
           每张卡得到平均梯度
                  ↓
              optimizer step
```

优点：

- 实现简单。
- 适合模型能放进单卡的情况。
- 扩展 batch size 很方便。

缺点：

- 每张卡都要保存完整模型参数、梯度、优化器状态。
- 模型太大时单卡放不下。
- 通信开销随参数量增长。

显存组成：

```text
参数 + 梯度 + 优化器状态 + 激活
```

对于 Adam：

- 参数：1 份
- 梯度：1 份
- 一阶动量 m：1 份
- 二阶动量 v：1 份
- 混合精度下还可能有 fp32 master weights

所以数据并行不能解决大模型参数显存瓶颈。

---

#### Tensor Parallel

Tensor Parallel，张量并行，把单个矩阵运算切分到多张 GPU 上。

核心思想：

> 模型的一层太大，单卡放不下或算不动，就把矩阵按行/列切开，多卡协同计算。

例如线性层：

$$
Y = XA
$$

如果按列切分 $A$：

$$
A = [A_1, A_2]
$$

则：

$$
Y_1=XA_1,\quad Y_2=XA_2
$$

最后 concat：

$$
Y=[Y_1,Y_2]
$$

在 Transformer 中常见切法：

1. **Attention Head 切分**
   - 不同 GPU 负责不同 attention heads。
   - 最后 concat 后做输出投影。

2. **MLP 切分**
   - `up_proj/gate_proj` 通常列切。
   - `down_proj` 通常行切，需要 all-reduce。

通信操作：

| 操作 | 作用 |
|---|---|
| all-reduce | 汇总各卡部分结果 |
| all-gather | 收集切分张量 |
| reduce-scatter | 汇总并切分输出 |

优点：

- 可以训练单卡放不下的大模型。
- 降低单卡参数和计算压力。
- 对超大矩阵乘法有效。

缺点：

- 层内通信频繁。
- 需要高速互联，如 NVLink / IB。
- 并行度过高时通信瓶颈明显。
- 实现复杂度高。

适合：

- 单层矩阵很大。
- 模型参数无法单卡容纳。
- GPU 间通信带宽足够高。

---

#### Deepspeed Zero

ZeRO，Zero Redundancy Optimizer，目标是消除数据并行中的冗余显存。

数据并行中，每张卡都保存完整：

```text
参数 Parameters
梯度 Gradients
优化器状态 Optimizer States
```

ZeRO 将这些状态切分到不同 GPU。

##### ZeRO-1

切分 optimizer states。

- 参数：每卡完整保存。
- 梯度：每卡完整保存。
- 优化器状态：分片保存。

节省 Adam optimizer states 显存。

##### ZeRO-2

切分 optimizer states + gradients。

- 参数：每卡完整保存。
- 梯度：分片保存。
- 优化器状态：分片保存。

进一步省显存。

##### ZeRO-3

切分 optimizer states + gradients + parameters。

- 参数：分片保存。
- 梯度：分片保存。
- 优化器状态：分片保存。

前向/反向时按需 all-gather 参数，用完释放。

最省显存，但通信最大。

对比：

| ZeRO 阶段 | 参数 | 梯度 | 优化器状态 | 显存节省 | 通信开销 |
|---|---|---|---|---|---|
| ZeRO-1 | 复制 | 复制 | 切分 | 中 | 低 |
| ZeRO-2 | 复制 | 切分 | 切分 | 高 | 中 |
| ZeRO-3 | 切分 | 切分 | 切分 | 最高 | 高 |

##### ZeRO-Offload

把部分状态 offload 到 CPU / NVMe：

- CPU offload：省 GPU 显存，但慢。
- NVMe offload：能训更大模型，但速度更慢。

##### ZeRO vs Tensor Parallel

| 维度 | ZeRO | Tensor Parallel |
|---|---|---|
| 切分对象 | 参数/梯度/优化器状态 | 矩阵计算 |
| 主要解决 | 显存冗余 | 单层计算/参数过大 |
| 通信位置 | 参数 gather / 梯度 reduce | 每层前后频繁通信 |
| 常见组合 | ZeRO + DP | TP + PP + DP |

### 1.6 训练

#### 参数量计算

以 Decoder-only Transformer 为例。

设：

- 层数：$N$
- hidden size：$d$
- FFN hidden size：$d_{ff}$
- vocab size：$V$
- attention heads：$h$
- KV heads：$h_{kv}$
- head dim：$d_h=d/h$

##### 1. Embedding 参数

Token embedding：

$$
V \times d
$$

如果 LM Head 不共享权重，还需要：

$$
d \times V
$$

很多 LLM 会 tie embedding 和 lm_head，也有模型不共享。

##### 2. Attention 参数

标准 MHA：

- $W_Q: d \times d$
- $W_K: d \times d$
- $W_V: d \times d$
- $W_O: d \times d$

总计：

$$
4d^2
$$

GQA 下：

- Q 仍为 $d \times d$
- K/V 输出维度为 $h_{kv}d_h$

K/V 参数：

$$
2d(h_{kv}d_h)
$$

Attention 总计：

$$
d^2 + 2d h_{kv}d_h + d^2
=
2d^2 + 2d h_{kv}d_h
$$

若 $h_{kv}=h$，退化为 $4d^2$。

##### 3. FFN 参数

普通 FFN：

$$
W_1: d \times d_{ff}
$$

$$
W_2: d_{ff} \times d
$$

总计：

$$
2dd_{ff}
$$

SwiGLU FFN：

- gate_proj：$d \times d_{ff}$
- up_proj：$d \times d_{ff}$
- down_proj：$d_{ff} \times d$

总计：

$$
3dd_{ff}
$$

##### 4. Norm 参数

LayerNorm/RMSNorm 每层通常有：

- attention norm：$d$
- ffn norm：$d$

每层约：

$$
2d
$$

Final norm：

$$
d
$$

相比 attention/ffn 通常可忽略。

##### 总参数近似

对于使用 MHA + SwiGLU 的 LLM：

$$
\text{Params}
\approx
Vd + N(4d^2 + 3dd_{ff})
$$

如果 $d_{ff}\approx \frac{8}{3}d$，则：

$$
3dd_{ff}\approx 8d^2
$$

每层约：

$$
12d^2
$$

总参数近似：

$$
\text{Params}
\approx Vd + 12Nd^2
$$

#### 显存计算

训练显存主要由以下部分组成：

```text
模型参数 + 梯度 + 优化器状态 + 激活值 + 临时 buffer
```

##### 1. 参数显存

如果 bf16/fp16 训练，参数每个元素 2 bytes：

$$
M_{\text{param}} = P \times 2
$$

其中 $P$ 是参数量。

例如 7B 模型 bf16 参数：

$$
7 \times 10^9 \times 2 \approx 14GB
$$

##### 2. 梯度显存

梯度通常也是 bf16/fp16 或 fp32，近似：

$$
M_{\text{grad}} \approx P \times 2
$$

##### 3. Adam 优化器状态

Adam 需要：

- 一阶动量 $m$
- 二阶动量 $v$
- 通常 fp32，各 4 bytes

$$
M_{\text{adam}} = P \times 8
$$

如果还有 fp32 master weight：

$$
M_{\text{master}} = P \times 4
$$

混合精度 Adam 粗略估算：

```text
参数 bf16: 2 bytes
梯度 bf16: 2 bytes
master weight fp32: 4 bytes
Adam m fp32: 4 bytes
Adam v fp32: 4 bytes
合计约 16 bytes / param
```

所以全参训练 7B：

$$
7B \times 16 \approx 112GB
$$

还不包括激活。

##### 4. 激活显存

激活与以下因素相关：

- batch size
- sequence length
- hidden size
- layer 数
- 是否使用 checkpointing
- attention 实现

粗略正比：

$$
M_{\text{act}} \propto B \cdot L \cdot d \cdot N
$$

长序列训练中，激活往往非常大。

##### 5. KV Cache 显存

推理时 KV Cache：

$$
M_{KV}
=
B \cdot L \cdot N \cdot 2 \cdot h_{kv} \cdot d_h \cdot \text{bytes}
$$

其中 2 表示 K 和 V。

GQA/MQA 能显著降低 $h_{kv}$，因此降低 KV Cache。

##### 常见省显存方法

| 方法 | 作用 |
|---|---|
| LoRA / QLoRA | 减少可训练参数和 optimizer states |
| Gradient Checkpointing | 用计算换激活显存 |
| ZeRO | 切分参数/梯度/优化器状态 |
| bf16/fp16 | 降低参数和激活显存 |
| FlashAttention | 降低 attention 激活显存 |
| Sequence Packing | 减少 padding 浪费 |
| Gradient Accumulation | 小 micro batch 模拟大 batch |
| CPU/NVMe Offload | 用速度换显存 |
| GQA/MQA | 降低推理 KV Cache |

#### 训练出现 NaN 的原因

训练出现 NaN 通常来自数值不稳定、数据异常或超参数设置不当。

##### 1. 学习率过大

表现：

- loss 突然 spike。
- gradient norm 爆炸。
- 参数更新过大导致 overflow。

解决：

- 降低 learning rate。
- 使用 warmup。
- gradient clipping。
- 检查 scheduler。

##### 2. 梯度爆炸

原因：

- 长序列。
- 深层网络。
- 初始化不合理。
- reward/advantage 过大。
- mixed precision overflow。

解决：

```text
clip_grad_norm_
loss scaling
advantage normalization
reward normalization
降低 lr
```

##### 3. fp16 overflow / underflow

fp16 数值范围有限：

- 大数容易 overflow 成 inf。
- 小梯度容易 underflow 成 0。

建议：

- 优先使用 bf16。
- 使用 AMP GradScaler。
- 对 logits / loss 做稳定计算。

##### 4. Softmax / Exp 溢出

如果 logits 太大：

$$
\exp(x)
$$

可能溢出。

稳定 softmax：

$$
\text{softmax}(x_i)=
\frac{\exp(x_i-\max(x))}
{\sum_j\exp(x_j-\max(x))}
$$

##### 5. log(0)

例如：

$$
\log p
$$

当 $p=0$ 时为 $-\infty$。

解决：

```python
p = torch.clamp(p, min=1e-8)
```

##### 6. 除 0

如归一化时：

```python
x / std
```

如果 `std=0` 会 NaN。

解决：

```python
x / (std + eps)
```

##### 7. sqrt 负数

由于数值误差，方差可能出现极小负值。

解决：

```python
var = torch.clamp(var, min=0.0)
```

##### 8. 数据异常

包括：

- 输入全 padding。
- label 全是 `-100`。
- token id 越界。
- 文本中存在非法字符。
- 样本长度超过模型限制。
- attention mask 错误。
- loss mask 错误。

##### 9. RLHF 特有 NaN

可能来自：

- reward 太大。
- advantage 方差过大。
- KL 爆炸。
- ratio 溢出。
- value loss 爆炸。
- entropy 过低。
- PPO clip 设置不合理。

解决：

| 问题 | 方法 |
|---|---|
| reward scale 大 | reward normalize / clip |
| advantage 大 | advantage normalization |
| ratio 爆炸 | ratio clip / KL penalty |
| KL 爆炸 | 增大 beta / early stop |
| value loss 爆 | value clip / 降低 critic lr |
| entropy 崩 | entropy bonus / 降 lr |

##### Debug Checklist

```text
1. 检查数据：input_ids / labels / attention_mask 是否合法
2. 检查 loss 是否第一步就是 NaN
3. 打印 logits max/min
4. 打印 grad norm
5. 检查是否有 inf 参数
6. 降低 lr 10 倍
7. 关闭 fp16，改 bf16 或 fp32 测试
8. 开启 anomaly detection
9. 对 log/div/sqrt/softmax 加 eps 或 clamp
10. 检查 reward / advantage / KL 是否异常
```
